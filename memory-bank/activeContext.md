## Active Decisions
- Auth: refresh token opaco rotado con detección de reutilización (familia de sesiones revocada) — implementado.
- Aislamiento tenant: ADMIN cross-tenant → 404; SUPER_ADMIN requiere `tenantId` explícito **en rutas de colección** (en rutas con `gameId` identifica solo el recurso) — implementado.
- Catálogo público: identidad **solo por slug** (`tenant`), `tenantId` prohibido en query; sin autenticación; lectura en `RepeatableRead`; ETag literal `"v<version>"` (solo `/` y `/version`); `/sync` sin ETag; Express etag global desactivado (`app.set('etag', false)`).
- Taxonomía dual: `tenantId=null` = biblioteca global, CRUD solo vía seed; visibilidad de lectura sí incluye globales — implementado.
- Publicar = mapeo **por slug** entre taxonomía global y del tenant; nada se salta en silencio (422 con lista de faltantes) — implementado.
- Soft delete conserva el slug reservado (409 slug existe) en taxonomía, BaseGame y TenantGame.
- Precios: `priceMode=MANUAL` fija `price` a mano; `priceMode=RULE` solo recibe precio vía `POST /admin/pricing/apply` (preview informa, apply ejecuta y sube `CatalogMetadata.version`) — Fase 7 implementada; volver a RULE limpia `price`.
- Versionado del catálogo: bump **incondicional** en toda mutación de catálogo (decisión 2026-10-09: juegos, media, taxonomía, pricing, config — sin condiciones de visibilidad; `updateGame` solo omite bump si no hay diff público). `planCatalogBump` = `upsert` con `version {increment}` **dentro** de la misma `$transaction` (sin pre-read; concurrentes serializan por row-lock → +2, verificado en smoke).
- Campos de biblioteca (`origin`, `baseGameId`, metadata copiada) inmutables tras publicar → 422 `LIBRARY_FIELDS_IMMUTABLE`.
- Auditoría: H1/H2/M1/M3/M4/L4/L6 cerrados en Fase 10; D2 cerrado en Fase 11 (`tokenVersion` aprobado); L1/L2/L3/L5 + D1 como deuda documentada (README §15).
- Backups: snapshot real con payload JSON en DB (aprobado por el usuario) — cubre tenant + plataforma, es la base del flujo pre-import de Fase 12; restore exclusivo `SUPER_ADMIN` con confirm `RESTAURAR`; nunca incluye passwords/sesiones/auditoría.
- Visibilidad del catálogo: `showUnavailable` default `false` (autoridad del spec §69 sobre el `true` del mock adminv2); `offerOffline` default `true`.
- Media publicId fijo por estructura §19 `tenants/{tenantId}/games/{slug}/cover|shot-N` + `overwrite:true` (el slug de juego es inmutable, así que el publicId también); reemplazo NO destruye el asset del mismo publicId (overwrite histórico), solo si el publicId anterior era distinto.
